# Компилятор Mini-PL

Компилятор, виртуальная машина и интерактивный отладчик учебного языка
**Mini-PL** — целиком в одном файле `minipl.py`, только на стандартной
библиотеке Python (3.8+). Никаких зависимостей ставить не нужно.

```
исходный текст
    -> лексический анализ      поток токенов
    -> синтаксический анализ   абстрактное синтаксическое дерево
    -> семантический анализ    таблица символов, проверка типов
    -> генерация кода          байткод стековой машины
    -> виртуальная машина      выполнение (или пошаговая отладка)
```

## Быстрый старт

```bash
python3 minipl.py examples/fizzbuzz.mpl              # скомпилировать и выполнить
python3 minipl.py examples/factorial.mpl --stdin 5   # передать данные для read
python3 minipl.py examples/debug_demo.mpl --debug    # запустить под отладчиком
python3 minipl.py -e 'print 2 + 2;'                  # выполнить код из аргумента
python3 minipl.py --help                             # полный список ключей
```

## Язык

```
var n : int := 5;          // объявление с инициализацией
var s : string;            // без инициализации: "" (для int — 0, для bool — false)

read n;                    // чтение слова из потока ввода (int или string)
print "n = ";              // print не добавляет перевод строки
print n;
print "\n";

for i in 1..n do           // цикл по диапазону; i менять внутри цикла нельзя
    print i;
end for;

while n > 0 do
    n := n - 1;
end while;

if n = 0 do
    print "ноль";
else
    print "не ноль";
end if;

assert (n >= 0);           // проверка во время выполнения
```

### Грамматика (EBNF)

```
<prog>   ::= <stmts>
<stmts>  ::= { <stmt> ";" }
<stmt>   ::= "var" <ident> ":" <type> [ ":=" <expr> ]
           | <ident> ":=" <expr>
           | "for" <ident> "in" <expr> ".." <expr> "do" <stmts> "end" "for"
           | "while" <expr> "do" <stmts> "end" "while"
           | "if" <expr> "do" <stmts> [ "else" <stmts> ] "end" "if"
           | "read" <ident>
           | "print" <expr>
           | "assert" "(" <expr> ")"
<expr>   ::= <expr> <binop> <expr> | <unop> <expr> | <opnd>
<opnd>   ::= <int> | <string> | <bool> | <ident> | "(" <expr> ")"
<type>   ::= "int" | "string" | "bool"
```

### Типы и операторы

| Тип      | Значение по умолчанию | Операторы                                   |
|----------|-----------------------|---------------------------------------------|
| `int`    | `0`                   | `+ - * / %`, сравнения, унарный `-`         |
| `string` | `""`                  | `+` (конкатенация), сравнения               |
| `bool`   | `false`               | `& \| !`, `=`, `<>`                          |

Приоритет операторов, от слабого к сильному:

```
|        &        = <> < <= > >=        + -        * / %        унарные ! - +
```

Неявных приведений типов нет: `1 + "a"` — ошибка. Целые 32-битные,
деление усекается к нулю (`-7 / 2 = -3`), переполнение — ошибка выполнения.
Комментарии: `// до конца строки` и `/* блочные, допускают вложенность */`.

### Отличия от исходной спецификации Mini-PL

Сознательные расширения, всё остальное соответствует спецификации:

* выражения разбираются с приоритетами — можно писать `a + b * c` без скобок;
* добавлены `if/else`, `while`, литералы `true`/`false`, операторы `<= >= <> % |`;
* переменная цикла `for` объявляется неявно, если не объявлена заранее;
* `&` и `|` вычисляются сокращённо: `false & (10 / 0 = 1)` не падает.

## Режимы работы

| Ключ                  | Что делает                                              |
|-----------------------|---------------------------------------------------------|
| `--tokens`            | печатает поток токенов с позициями                       |
| `--ast`               | печатает синтаксическое дерево с выведенными типами      |
| `--symbols`           | печатает таблицу символов (слоты, типы, использование)   |
| `--dis`               | печатает дизассемблированный байткод                     |
| `--check`             | только проверить программу, не запускать                 |
| `--trace`             | печатать каждую выполняемую инструкцию и стек операндов  |
| `--debug`             | запустить интерактивный отладчик                         |
| `--emit ФАЙЛ`         | сохранить байткод                                        |
| `--from-bytecode`     | выполнить ранее сохранённый байткод                      |
| `--stdin ТЕКСТ`       | данные для `read` (есть и `--stdin-file`)                |
| `--max-steps N`       | прервать выполнение после N инструкций                   |
| `--strict`            | считать предупреждения ошибками                          |
| `--no-warnings`       | не показывать предупреждения                             |
| `--color auto\|always\|never` | раскраска сообщений                              |

Коды возврата: `0` — успех, `1` — ошибка компиляции, `2` — ошибка выполнения,
`3` — ошибка использования (файл не найден, не указана программа).

Пример байткода (`--dis`):

```
0008  L9     LOAD    2     // i : int
0009  L9     LOAD    3     // $limit#9:1 : int
0010  L9     LE            // продолжать цикл?
0011  L9     JMPF    21    // -> 21
```

## Обработка ошибок

Ошибки не останавливают компилятор на первой проблеме: лексер, парсер и
семантический анализатор собирают все найденные ошибки за один проход
(парсер восстанавливается по точке с запятой и ключевым словам). Каждое
сообщение показывает файл, строку, колонку, подчёркнутый фрагмент и подсказку.

```
error[E3003]: нельзя инициализировать переменную типа int выражением типа string
 --> program.mpl:1:16
  |
1 | var x : int := "hello";
  |                ^^^^^^^ ожидалось выражение типа int
```

Коды сгруппированы по фазам:

| Диапазон | Фаза                  | Примеры                                              |
|----------|-----------------------|------------------------------------------------------|
| `E1xxx`  | лексический анализ    | незакрытая строка, незакрытый комментарий, чужой символ |
| `E2xxx`  | синтаксический анализ | пропущена `;`, незакрытая скобка, лишний токен       |
| `E3xxx`  | семантический анализ  | нет объявления, повтор объявления, несовпадение типов, запись в счётчик цикла |
| `E4xxx`  | выполнение            | деление на ноль, провал `assert`, плохой ввод, переполнение, лимит шагов |

Предупреждения (например, `E3009` — неиспользуемая переменная) не мешают
запуску, но `--strict` превращает их в ошибки.

## Отладчик

```bash
python3 minipl.py examples/debug_demo.mpl --debug
```

| Команда                | Действие                                              |
|------------------------|-------------------------------------------------------|
| `run`, `r`             | перезапустить программу с начала                       |
| `continue`, `c`        | продолжить до точки останова или до конца              |
| `step`, `s`, `n`       | шаг по исходному коду (одна строка)                    |
| `stepi`, `si [N]`      | шаг по байткоду                                        |
| `break 12`, `b *42`    | точка останова на строке или на инструкции             |
| `break 12 if i > 3`    | условная точка останова                                |
| `delete [N]`, `enable/disable N` | управление точками останова                  |
| `watch x`, `unwatch x` | остановка при изменении переменной                     |
| `print x * 2`, `p`     | вычислить выражение в текущем состоянии                |
| `vars [all]`           | значения переменных (`all` — со служебными слотами)    |
| `set x := 42`          | изменить значение переменной на лету                   |
| `stack`                | стек операндов виртуальной машины                      |
| `list [строка]`        | исходный код вокруг текущей строки                     |
| `dis [N]`              | байткод вокруг счётчика команд                         |
| `where`, `bt`          | где сейчас находится выполнение                        |
| `help`, `quit`         | справка и выход                                        |

Пустая строка повторяет предыдущую команду. Выражения в `print` и в условиях
точек останова разбирает и проверяет тот же компилятор, что и программу, —
поэтому `p i * 2 + 1` знает типы и видит переменные программы.

Пример сессии:

```
(minipl) break 14 if i = 3
создана точка останова #1 строка 14 если i = 3, срабатываний: 0
(minipl) continue
остановка на точке #1 строка 14 если i = 3, срабатываний: 1
строка 14:     total := total + i * 2;
след. инструкция 0019  L14    LOAD    1     // total : int
(minipl) p total
total = 6
(minipl) watch total
наблюдение за 'total' включено
(minipl) c
наблюдение: total = 12 (было 6)
```

При ошибке времени выполнения отладчик не завершается: он печатает
диагностику и оставляет состояние машины доступным для осмотра
(`vars`, `stack`, `p ...`).

## Устройство `minipl.py`

Файл разделён на пронумерованные части — по одной на каждый этап:

| Часть | Содержимое                                                    |
|-------|---------------------------------------------------------------|
| 1     | позиции и диапазоны в исходном тексте                          |
| 2     | диагностика: коды ошибок, цвета, вывод с подчёркиванием         |
| 3–4   | значения и система типов (таблицы допустимых операций)          |
| 5–6   | токены и лексический анализатор                                 |
| 7–8   | AST и парсер рекурсивного спуска с восстановлением после ошибок |
| 9–10  | таблица символов и семантический анализ                         |
| 11–12 | набор команд, `Chunk`, дизассемблер и генератор кода            |
| 13    | виртуальная машина                                              |
| 14    | конвейер компиляции (`compile_source`)                          |
| 15    | интерактивный отладчик                                          |
| 16    | разбор аргументов командной строки                              |

Модуль можно использовать и как библиотеку:

```python
import minipl

compilation = minipl.compile_source(minipl.Source("print 2 + 2;", "demo.mpl"))
if compilation.ok:
    minipl.VM(compilation.chunk).run()
else:
    compilation.diagnostics.report()
```

## Тесты

```bash
python3 -m unittest discover -s tests -v
```

95 тестов покрывают лексер, парсер (включая восстановление после ошибок),
проверку типов, генерацию кода, виртуальную машину, ошибки времени
выполнения, сериализацию байткода, отладчик и командную строку.
